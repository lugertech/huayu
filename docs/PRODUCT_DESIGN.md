# 从 tldraw computer 到画语：产品判断与实现

调研与实现日期：2026-10-24。

## 产品应该成为什么

画语适合成为一个把资料、草图和录屏转化为作品的本地创作工作台。它的核心过程应该是：放入材料，指明意图，看到结果，直接修改，再沿着结果继续。白板提供思考和操作的空间，连接线表达材料之间的依赖，录屏提供可以回溯的事实来源。

现有项目已经具备文字、图片、网页、语音、文件、图表、绘图和录屏分析能力。当前更需要打磨这些能力之间的衔接，让一个实际任务能够顺畅完成。单纯增加组件类型，会加重学习负担。

## 本轮已经落实

### 1. 通过组件连线开始创作

从左侧添加组件，将材料连入创作指令，写下要求后在节点上运行。图片、语音、网站、文件和图表接收前置组件的输出。后续方向通过连线表达，新建步骤避开已有内容，组件与连接可以一起撤销。

### 2. 组件按各自规则接收与输出内容

文本组件用前置输出替换正文。网站组件读取前置材料，生成并预览 HTML。画框提供一张整体快照。图表结构与传给后续组件的摘要分开保存，AI 解答只使用自身选框内的原生内容。具体规则见 [组件输入与输出](./COMPONENT_PARITY.md)。

### 3. 让录屏成为可继续使用的材料

录屏可以通过「转为创作画布」生成包含内容记录、转写和创作指令的项目。单句转写和单个章节也能直接生成独立创作画布，章节仅提取对应时间范围内的转写。

材料是可以编辑的普通文字卡片，同时保留来源录屏和时间位置。点击来源可返回分析页面并定位播放器。转换本身不调用模型；录屏中的事实内容可以先检查，再用于创作。

### 4. 收起干扰，修复细节

卡片标题收紧为 36 像素。各组件工具沿用旧版的位置并常驻组件内部：图片左下角上传／下载、右下角比例，指令左下角联网搜索；语音、文件、网站与图表也保留各自工具。文本不显示附加工具条。选区创作面板、选中后的操作浮层和底部选区工具条已移除。

选中卡片后，可拖动左右端口连接已有素材或后续步骤，目标会高亮并显示预览线；拖到空白处可接续新步骤，也支持点按或键盘打开菜单。新连线标注素材含义；重复连接、循环和跨页面连接会被拦截。卡片和连线作为一次操作撤销，新步骤会避开已有内容。旋转及画框内卡片使用实际端口坐标；聚焦输入框不会单独滚动卡片图层。

运行中的路径以流动虚线标记，卡片显示等待、运行、失败或停止状态与耗时。生成结果记录内容指纹、完成时间和耗时，刷新后仍可检查。素材或要求变化时，下游结果显示「需更新」，可只更新受影响分支；锁定结果继续复用。运行期间输入变化也不会把旧结果误标为最新。停止或失败保留已有作品，模型连接信息不进入这些记录。

这些改动沿用现有中性配色、侧栏和深浅色模式。模型配置仍在设置中，仅由浏览器保存；本轮没有增加后端模型接口。

### 5. 查看与修改作品

文字、图片、网页使用统一的作品窗口。双击组件标题或选中后按 Enter 可打开；网站内部的全屏按钮在新窗口预览网页。关闭窗口后返回当前作品，切换已有版本时画布跟随定位。

文字默认以 Markdown 阅读，编辑修改的是生成正文，原始要求继续保留。网页可以交互预览、切换桌面或手机尺寸、编辑 HTML 并检查实时预览；已有的脚本隔离与网络限制保持生效。编辑草稿按项目、页面和作品分别保存在浏览器，关闭窗口后可继续；其他页面更新原文时会保留草稿并提示冲突。修改可以保存或撤销，后续相连组件读取已保存的实际内容。

图片支持适应窗口、原始尺寸、缩放与拖动；放大后的拖动有边界，避免丢失图片。裁剪和旋转按原始像素生成本地 PNG，保存为相连的新图片，保留原图。复制操作写入实际图片，下载保留文件格式；文字和网页分别导出 Markdown 与 HTML。

这落实了参考材料中「结果成为下一轮材料」的设计方向。当前版本列表是主动派生作品的导航，不记录每次文字编辑的快照，也不提供并排比较。

## 后续的优先顺序

以下属于产品建议，尚未实现。

1. **深化比较与标注。** 在现有版本列表之上，支持并排比较两个方向；文字批注和自由箭头需要可明确纳入某次请求的选区范围。
2. **深化直接编辑。** 网页已有 HTML 编辑与实时预览，后续可补充元素级调整与图表作品工作台；保持手工修改能够继续作为生成输入。
3. **约束绘图助手的操作范围。** 用选区或画框声明可操作区域，展示拟修改内容，允许逐次撤销；把助手的讨论放在独立的批注层。
4. **深化录屏与来源。** 支持连续选择多个片段、放入已有项目、定位原句和跨作品查看引用。本轮先把片段到新画布的链路打通。

不急于加入无限循环、自动运行整个画布、复杂变量系统、拟人化多助手或更多常驻面板。是否引入这些能力，应由真实任务中反复出现的需求决定。

## 用实际任务判断设计

- 从已有作品派生一个新方向，能否通过「选中 → 写要求 → 开始」完成？
- 用户能否在调用模型前确认使用哪些材料？
- 生成结果是否可以直接编辑，并继续作为下一步输入？
- 一个录屏片段能否成为创作材料，并回到原始时间点核对？
- 误操作后能否撤销，迷失视口后能否迅速返回？

验证记录见 [VERIFICATION.md](./VERIFICATION.md)。保留 Excalidraw 作为白板基础；本次学习采用设计思想，没有重新引入 tldraw SDK 或复制其实现。

## 完整作品示例 — 2026-11-03

查看了 [tldraw Computer](https://computer.tldraw.com/) 的 [Story Generator](https://computer.tldraw.com/t/m6rf2ckVFbRc7r7yZt9oGM) 与 [Invention Inventor](https://computer.tldraw.com/t/9sfvz9vrz5nUsFRspwTJXm)。它们把一个具体任务展开为多路输入、处理分支和下游作品；任务本身比单独介绍某种输出格式更容易理解。

画语据此将六个场景模板扩展为完整示例。用具体素材说明“从哪里开始”，通过共享输入与分支表达关系，再用文稿、插画和可操作网页说明“最后能得到什么”。示例内容均为作者编写，不标注虚构运行耗时或模型执行记录。在应用的示例项目中，可以查看内容、回溯指令并继续编辑。
