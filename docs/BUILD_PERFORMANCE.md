# 构建分块与字体资源

验证日期：2026-10-26。工具链为 Vite+ 1.4.0、Vite 8.3.5、Rolldown 1.2.15，验证环境为 macOS、Node.js 24.22.1。

## 当前实现

本轮参考 timetable 的原生分包与构建预算做法，分别配置 Web 和官网。两端都使用 [Rolldown codeSplitting](https://rolldown.rs/reference/OutputOptions.codeSplitting)，保留已有路由与功能的动态导入。

- Web 按使用入口拆分 Excalidraw，保留模块依赖的执行顺序。`strictExecutionOrder` 用于处理手动分包后的初始化顺序，避免出现跨分块的未初始化函数调用。
- Web 使用 `$initial` 标签，仅合并已有静态依赖中的应用代码、React 客户端运行时与基础 UI。共享分块排除页面入口和虚拟 Worker 入口，避免在 Worker 中执行首页代码；React 服务端渲染模块继续按需加载。
- 设置与快速查找在首次打开时加载，之后保留组件实例，覆盖侧栏、快捷键和模型设置跳转入口。首页单独导入轻量 Tooltip Provider，画布使用的 Tooltip 内容继续按需加载。
- Excalidraw 0.18.1 的一个预打包模块内嵌两段 Base64 WebAssembly。`apps/web/build/external-font-wasm.ts` 将原始二进制原样输出为两个带内容哈希的 `.wasm` 资源，并在字体模块需要它们时并行加载；不修改安装包或提交二进制副本。
- 字体 Worker 保留独立入口，启动时暂存消息，等异步字体模块注册处理函数后再逐条交付。Worker 内的动态导入不创建依赖 DOM 的预加载链接。该处理保留后台字体子集计算，避免消息在初始化期间丢失。
- 官网将 React 客户端运行时与应用、文档代码分开，继续执行 SSR 与 46 个中英文页面的预渲染。
- 构建生成 `dist/bundle-budget.json`，记录最终写入的分块字节数、gzip 大小及是否属于首页静态依赖。应用分块超过预算、首页体积超限，或按需依赖及 Worker 入口被合并进首页时，构建直接失败。

## 体积与取舍

下表使用十进制字节。首页 gzip 是 HTML 入口静态导入图中各 JS 文件的 gzip 大小之和，排除动态导入和字体 Worker；它不是浏览器首屏耗时测量。

| 指标 | 分块优化前 | 首轮优化 | 本轮优化 |
| --- | ---: | ---: | ---: |
| Web 最大 JS 分块 | 1,821,003 | 712,716 | 712,716 |
| 官网最大 JS 分块 | 628,770 | 408,523 | 408,523 |
| Web 首页 JS gzip | 219,401 | 232,258 | 214,479 |
| 官网首页 JS gzip | 208,458 | 209,314 | 209,314 |

字体二进制分别为 727,190 和 590,665 字节，SHA-256 与从原依赖内嵌数据解码的结果一致。它们属于按需加载的字体资源。

首轮保留执行顺序后，Web 首页 gzip 增加了 12,857 字节。本轮保持 `strictExecutionOrder`，通过静态依赖合并和缩小首页依赖范围减少 17,779 字节，首页静态 JS 分块从 16 个降至 6 个。最终比首轮优化前少 4,922 字节；这些体积变化不等同于首屏耗时测量。

## 构建预算

| 范围 | 限制 |
| --- | ---: |
| 应用及其他 JS 分块 | 500,000 字节 |
| 单模块发布的 `@pdf-lib/fontkit` | 750,000 字节 |
| 单模块发布的 `@mermaid-js/parser` | 700,000 字节 |
| Web 首页 JS gzip | 219,000 字节 |
| 官网首页 JS gzip | 215,000 字节 |

两个第三方例外要求分块内所有模块都属于对应依赖，不能用于放宽混合应用代码的预算。Web 的 Vite 警告阈值由 1,800 KB 降为 750 KB，官网仍为默认 500 KB；两端构建均无大分块警告。

## 验证与升级

```sh
vp run check
vp run test
vp run build:web
vp run build:site
```

前端 150 项、发布工具 6 项和 Rust 集成 7 项测试通过。回归覆盖字体二进制内容、请求失败、并行加载、Worker 入口 URL 和初始化期间消息交付。本轮增加实际构建回归，验证独立 Worker 不计入首页，以及手动分组合并 Worker 与首页时构建失败。预算报告与最终文件体积逐项核对一致。

浏览器使用独立临时实例检查首页、设置首次打开与重开、快捷搜索及模型设置跳转、白板冷启动、中英文文字与手写体 SVG 导出。前轮已检查官网图片页签与文档页，本轮重新构建官网。最终字体 Worker 没有超时或回退主线程；导出的 4 份 WOFF2 子集共 6,424 字节，与前轮输出逐字节一致。两个二进制资源的 HTTP 状态、`application/wasm` 类型和 WebAssembly 编译均通过。

升级 Excalidraw 时，应重新核对预打包字体模块、`subset-worker.chunk.js` 的导出及消息协议，运行上述检查，并实际导出包含手写体和中文的 SVG。若依赖已支持外部 WebAssembly，可用上游入口替换当前构建转换。
