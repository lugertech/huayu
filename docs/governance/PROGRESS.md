# 架构治理进度

本次审计从 `c55d275` 开始。现有六条页面路由、浏览器模型配置、画布和录制恢复、工作流取消、HTTP 与 WebSocket 契约是迁移基线。开发者可以从[系统架构](../ARCHITECTURE.md)和[状态机](../STATE_MACHINES.md)找到原有设计。

## 工作顺序与验收

1. 在独立 worktree 记录源文件、运行时模块、存储和请求的所有者，结合历史修复确认兼容要求。
2. 以画布、录制与工作流、模型、资源读取、Rust 服务、工具链为并行范围。先验证现有调用方，再决定复用既有实现、收回到所属模块或保留差异。
3. 每批从可运行的行为基线开始。迁移全部调用方和测试替身，清理旧实现，分别提交。由另一位开发者或 Agent 阅读差异、调用路径与验证结果。
4. 集成后执行仓库检查、测试与 Web 生产构建。对实际依赖和持久化契约使用可重复执行的检查。记录仍需产品决策或外部环境验证的项目。

## 复审与回滚

每批先在独立工作树对真实入口或已有行为做基线验证，再由另一位 Agent 或集成人核对差异、调用方和数据边界。对图表布局与快照、服务端投影、模板数据、生成编排以及模型配置分别复审。检查规则采用反例验证；例如只在 lint override 注册插件曾让真实静态环通过，顶层注册后已能拒绝同样的环。集成冲突解决后再次运行全仓检查与生产构建。

本地提交按依赖顺序排列。单独撤回可使用 `git revert <commit>`；当后续提交依赖已迁移的接口，先按逆序撤回依赖批次。用户数据兼容性基线是 `c55d275`。这些批次没有数据库结构迁移、配置格式转换或重写已有项目。还原源码不会撤销运行服务期间用户主动创建或编辑的项目。

## 架构约束的验证范围

- Web 依赖检查覆盖四项生产约束。功能模块不得导入页面，画布引擎不得导入画布交互组件，通用 API 不得导入浏览器模型、工作流或业务功能，独立素材库与画布不得互相导入。类型、重导出和字面量动态导入均按 TypeScript 配置解析。测试可以跨层组合真实入口。
- `import/no-cycle` 检查 Web 静态值导入。包含类型与动态边的完整模块图另有两处双向关系。模型配置构造连接错误，错误类仅使用 capability 类型；编辑器按需加载导出实现，导出实现只使用编辑器类型。两处反向类型引用都会在运行前擦除。
- Rust 的 crate 依赖环由 Cargo 拒绝；`6f22e7a` 另外禁止 core 常规直接依赖 SeaORM 或 Axum、store 常规直接依赖 Axum。实际反例覆盖 Cargo 重命名、可选和目标平台条件依赖。标准库 I/O 与运行时消息流仍需通过代码审查和行为测试核实。
