# 架构治理进度

本次审计从 `c55d275` 开始。现有六条页面路由、浏览器模型配置、画布和录制恢复、工作流取消、HTTP 与 WebSocket 契约是迁移基线。开发者可以从[系统架构](../ARCHITECTURE.md)和[状态机](../STATE_MACHINES.md)找到原有设计。

## 工作顺序与验收

1. 在独立 worktree 记录源文件、运行时模块、存储和请求的所有者，结合历史修复确认兼容要求。
2. 以画布、录制与工作流、模型、资源读取、Rust 服务、工具链为并行范围。先验证现有调用方，再决定复用既有实现、收回到所属模块或保留差异。
3. 每批从可运行的行为基线开始。迁移全部调用方和测试替身，清理旧实现，分别提交。由另一位开发者或 Agent 阅读差异、调用路径与验证结果。
4. 集成后执行仓库检查、测试与 Web 生产构建。对实际依赖和持久化契约使用可重复执行的检查。记录仍需产品决策或外部环境验证的项目。
